# VisionDoctor 黑客松 MVP 项目契约

## 1. 产品目标

VisionDoctor 是一个面向 YOLO Detection 数据集的“体检与修复决策”单体 Agent。它接收用户上传的数据集 ZIP，在不训练模型、不自动修改原始标签的前提下，发现数据与标注风险、解释风险、给出可执行的修复优先级，并产出便于演示和复核的报告。

本项目首先服务于黑客松演示：流程完整、结果可解释、默认离线可运行、安全边界明确，比覆盖更多数据格式或建设生产级平台更重要。

## 2. 输入与输出

### 2.1 输入

- 单个 ZIP 压缩包。
- 压缩包内容为 YOLO Detection 数据集：必需的唯一 `data.yaml` 和至少一个可解析的训练图片目录；支持 split-first、images-first 和 flat 布局，`val`/`test` 可选，标签目录缺失时按缺失标签继续分析。
- ZIP 可以直接以数据集内容为根或包含一个数据集外层目录；唯一的 `data.yaml` 决定数据集根，其他普通文件类型可以存在并被忽略。
- 标签行采用 `class_id x_center y_center width height`，坐标为归一化数值。
- MVP 只接受受支持的图片扩展名和普通文件；具体白名单与资源上限须在实现阶段集中配置并测试。

### 2.2 输出

- 数据集解析摘要和类别分布。
- 标注异常、图片质量、重复图片等问题清单，包含可定位的文件、问题类型、严重度和证据。
- Health Score、分项结果、计算依据和免责声明。
- LLM 诊断或 deterministic fallback 诊断；两者应遵守同一结构化输出契约。
- Issue Explorer 所需的结构化数据与 Streamlit 交互界面。
- 机器可读 JSON 报告和便于分享的静态 HTML 报告。
- 修复建议和优先级；不得直接改写用户的原始标签或图片。

## 3. 功能范围

MVP 必须形成一条可演示的端到端链路：

1. 安全接收并解压 ZIP。
2. 识别唯一数据集根，安全解析 `data.yaml` 的类名与相对本地 split 路径，并对缺失路径执行无歧义的 split-first、images-first 或 flat 布局发现。
3. 检测标注异常，包括但不限于：缺失/空标签、孤立标签、字段数错误、非数值、非法类别、越界或非正尺寸框。
4. 检测图片质量问题，包括但不限于：无法解码、尺寸过小、模糊、过暗或过亮；阈值必须可解释且可配置。
5. 检测完全重复或近重复图片，并提供证据与分组。
6. 分析类别数量、占比和明显不平衡。
7. 基于可追溯规则计算总 Health Score 和分项分数。
8. 将检测事实转为结构化诊断和修复建议；可选使用 LLM，但必须支持等价可用的确定性回退路径。
9. 提供 Issue Explorer、JSON/HTML 报告和 Streamlit Demo。

## 4. 非目标

- 不支持 COCO、实例/语义分割、姿态估计或其他标注格式。
- 不进行模型训练、微调、重新训练或模型效果评测。
- 不使用 SAM 自动标注。
- 不自动修改、覆盖或删除原始标签和图片。
- 不采用 Multi-Agent 或 LangGraph。
- 不引入 PostgreSQL、Redis 或其他数据库。
- 不建设登录、账号或权限系统。
- 不建设 React 前端。
- 不进行外部部署。
- 不在本项目任务中执行 Git 提交或推送。

## 6. 核心技术约束

- 使用 Python 实现，并以 Streamlit 提供黑客松 Demo。
- 核心检查、评分和确定性诊断必须与 UI 解耦，可由测试直接调用。
- 内部问题记录和最终 JSON 使用明确、稳定、可验证的 schema。
- 检测结果必须保留证据来源；LLM 不得生成或覆盖检测事实。
- 相同输入和相同配置下，非 LLM 检查及评分应保持确定性。
- 阈值、权重、支持的扩展名和资源上限应集中配置，避免散落的魔法数字。
- 不使用数据库；一次分析的状态保存在受控的临时工作区或内存中。
- 不修改用户原始归档；任何派生产物写入独立输出位置。
- 后续实现不得把“推荐目录结构”或计划状态误写为已经完成的能力。

## 7. 安全要求

- 在写入前验证 ZIP 条目：拒绝绝对路径、盘符路径、`..` 路径穿越、符号链接及其他非普通文件。
- 解压目标必须位于每次任务独立的临时目录中，并以解析后的规范路径再次验证边界。
- 设置并测试上传大小、条目数量、单文件大小、解压后总大小和压缩比上限，以降低 ZIP bomb 与资源耗尽风险。
- 采用文件扩展名白名单并实际解码图片；不得执行归档内文件。
- 对损坏、加密或不受支持的归档安全失败，向用户提供可理解的错误，不泄露服务器路径或密钥。
- 上传数据、临时文件、报告和日志遵循最小留存原则；任务结束应清理临时数据。
- 日志和报告不得包含 API Key、凭证或无关的敏感环境信息。
- 外部 LLM 调用必须是可选能力；若启用，应最小化发送内容、设置超时和错误回退，并明确告知数据可能离开本地环境。
- HTML 报告与 UI 中的文件名、标签内容和模型文本必须转义，避免注入。
- 原始数据始终只读；修复建议仅供用户决策。

## 8. Health Score 的性质与免责声明

Health Score 是面向数据整理的启发式风险指标，不是医学诊断、数据集“真实性”证明、模型精度预测或训练成功保证。分数只能反映本工具已实现检查项、当前阈值和权重下观察到的问题。

报告必须同时展示总分、分项、扣分原因、受影响样本数和配置版本，避免把单一数字解释为绝对质量。阈值或权重变化可能使同一数据集得分变化；小数据集和特殊领域数据尤其需要人工复核。分数不得替代领域专家判断，且不得宣称未检测到的问题不存在。

## 9. 无 API Key 时的完整运行保证

- API Key 不是安装、启动、分析、评分、浏览问题或导出报告的前置条件。
- 默认路径必须在完全离线、无任何外部凭证时完成安全解压、解析、全部确定性检查、Health Score、确定性诊断、Issue Explorer、JSON/HTML 报告和 Streamlit Demo。
- 未配置 Key、SDK 不可用、超时、限流或响应校验失败时，系统自动使用 deterministic fallback，而不是中止分析。
- LLM 只允许基于已有结构化事实改写或排序建议；不得改变检测结果和 Health Score。

## 10. 最终验收条件

完成的 MVP 必须同时满足：

1. 对合法的最小 YOLO Detection ZIP，可从 Streamlit 上传并完成端到端分析。
2. 对路径穿越、超限、损坏或不支持的 ZIP 安全拒绝，且不在受控目录外写文件。
3. 对约定的标注异常、图片质量、重复图片和类别分布场景，有可重复的自动化测试和可定位结果。
4. Health Score 可复算，报告展示分项、扣分依据、配置版本和免责声明。
5. 未配置任何 API Key 且无法访问外部服务时，所有必需功能仍可完整运行。
6. LLM 路径启用时有 schema 校验、超时和 deterministic fallback，且不改变底层事实。
7. Issue Explorer 能按严重度、类型、类别或文件定位问题，并展示必要证据。
8. JSON 与 HTML 报告由同一分析结果生成，关键计数、问题和分数一致。
9. 原始图片与标签未被修改；临时上传数据按约定清理；报告内容经过安全转义。
10. 项目说明、运行命令、限制和测试结果与实际仓库状态一致，不把计划能力描述成已实现。
